# AGENTS.md

Guidance for AI coding agents working on this repo. For humans, see README.md.

This is a NixOS flake describing all of Zoe's machines. It is checked out at
`/etc/nixos` on each machine and is a **public** GitHub repo
(`zoeleu/nixos`), so everything committed is visible to anyone.

## Layout

```
flake.nix               # every directory in hosts/ becomes nixosConfigurations.<dir>
modules/common.nix      # system settings shared by all hosts
modules/ci.nix          # ci.heavyPackages option (slow packages CI builds in parallel)
modules/secrets.nix     # sops-nix: secrets/*.yaml decrypted with each machine's SSH host key
modules/auto-upgrade.nix # machines update from the `built` branch (moved by CI)
modules/avatar.nix      # zoe's profile picture = her GitHub avatar (fetched daily)
modules/branding.nix    # boot splash theme, quiet boot, fastfetch (colours: pkgs/artwork.nix)
modules/os-command.nix  # the `os` command (status/update/rollback/...), weekly GC, boot-menu limit
pkgs/artwork.nix        # THE accent colour + recoloured NixOS snowflake (logo, wallpaper); used by all of the above and the installer
secrets/                # encrypted secrets (sops); .sops.yaml = who can decrypt
home/common.nix         # zoe's Home Manager config shared by all hosts
home/plasma.nix         # Plasma look (plasma-manager): Breeze Dark, accent, wallpaper; zoe everywhere + deck's `deck` user
hosts/<name>/default.nix               # per-machine config; hostname = <name>
hosts/<name>/hardware-configuration.nix  # generated by nixos-generate-config, don't hand-edit
hosts/deck/ccache.nix   # compiles Jovian's kernel + Mesa forks through ccache (CI keeps the cache)
hosts/deck/pxe.nix      # PXE helper for the LAN (dnsmasq proxy-DHCP + iPXE -> nix.zoe.dev.br/netboot)
hosts/deck/touch-unlock.nix # disk passphrase on the touchscreen (unl0kr), boot splash only after unlocking
hosts/<name>/disko.nix  # disk layout (partitions, LUKS, swap) for hosts installed by the ISO
hosts/<name>/disk.nix   # which disk (by-id); written by the installer, like hardware-configuration.nix
installer/              # installer as ISO (iso.nix) and network boot (netboot.nix); iso.yml publishes both
                        #   common.nix = kiosk session (sway, tabs) + helpers; gui.py = the window;
                        #   install-nixos.sh = the engine that does everything (also runs alone on a console)
tests/                  # NixOS VM tests (flake `checks`): touch-unlock, installer-gui
.github/workflows/build.yml   # prepare -> heavy (parallel) -> build -> weekly commit
.github/actions/{setup,finish-push}/  # shared CI steps
```

Hosts:
- `deck`: Steam Deck LCD running Jovian NixOS. Separate auto-login `deck`
  user for Gaming Mode, `zoe` is the admin with an fscrypt-encrypted home.
- `desktop`: AMD RX 9060 XT PC, Plasma + Plasma Login Manager, LUKS
  (passphrase at boot) then auto-login into zoe, key-only SSH, Incus for
  AI-agent VMs (zoe in the restricted `incus` group, never `incus-admin`).
  Not installed yet: its `hardware-configuration.nix` and `disk.nix` are
  missing on purpose (the installer ISO writes them),
  so nixosConfigurations skips it (see flake.nix). ciConfigurations builds
  it with the explicit build-only hosts/desktop/ci.nix profile (tmpfs root,
  no bootloader). CI uses the real configuration once the generated files
  exist. Never write those generated files by hand.

## Where things go

- Shared by every machine: `modules/common.nix` (system) or
  `home/common.nix` (zoe's dotfiles/apps via Home Manager).
- One machine only: `hosts/<name>/default.nix`.
- Keep host-specific policy out of `common.nix`. SSH auth rules, auto-login,
  fscrypt, desktop environment, kernel and `nix.settings.max-jobs` are
  per host on purpose.
- New flake inputs: add `inputs.nixpkgs.follows = "nixpkgs"` when the input
  has a nixpkgs input. Modules get `inputs` through `specialArgs`.
- A slow-to-compile package for one host: add it to `ci.heavyPackages` in
  that host's `default.nix`. Kernel, graphics drivers and PipeWire are
  already added for every host by `modules/ci.nix`.
- ccache (`hosts/deck/ccache.nix`): only wrap C/C++ packages that
  cache.nixos.org doesn't have (Jovian's). Wrapping changes a package's
  hash, so wrapping anything from nixpkgs makes it miss the official cache
  and rebuild. The wrapper falls back to the plain compiler when
  `/var/cache/ccache` isn't in the sandbox, so machines need no setup.

## Verify changes before committing

There is no test suite; evaluating every host is the test. Nix only sees
files tracked by git, so `git add` new files first.

```bash
export NIX_CONFIG="experimental-features = nix-command flakes"
nix eval --json .#nixosConfigurations --apply builtins.attrNames          # hosts
nix eval --raw .#nixosConfigurations.<host>.config.system.build.toplevel.drvPath   # must succeed for every host
nix build --dry-run .#nixosConfigurations.<host>.config.system.build.toplevel      # what would compile
# Also evaluate/dry-run every ciConfigurations host (includes pre-install desktop):
nix eval --raw .#ciConfigurations.<host>.config.system.build.toplevel.drvPath
nix run nixpkgs#actionlint -- -ignore SC2016 .github/workflows/build.yml  # after editing CI
nix build -L .#checks.x86_64-linux.touch-unlock    # after touching the Deck's boot/unlock (VM test, ~2 min)
nix build -L .#checks.x86_64-linux.installer-gui   # after touching installer/ (VM test; screenshots in ./result)
```

Don't run `nixos-rebuild switch` on someone's machine as a way of testing;
evaluate instead, and leave applying to Zoe.

## Rules

- **No plaintext secrets in the repo.** It's public. Passwords, tokens and
  private keys go into `secrets/*.yaml`, encrypted with sops (`.sops.yaml`
  lists who can decrypt: zoe's age key + each machine's SSH host key), and
  are read through `sops.secrets` (see `modules/secrets.nix`). Public SSH
  keys are fine in plain text. Edit a secret with
  `SOPS_AGE_KEY=<Bitwarden "sops: age key"> sops secrets/<file>.yaml`; never
  commit a decrypted copy. A new machine must be added to `.sops.yaml` +
  `sops updatekeys` (the installer does it) or its secrets won't decrypt.
- **The binary cache must stay private.** It's our own Attic server at
  https://cache.zoe.dev.br/nixos (vps-main; see README) and it contains
  unfree packages (Steam, claude-code, Chrome...), which is only fine because
  nobody without a token can download them. Never make the `nixos` cache
  public and never publish its tokens. Tokens live in Bitwarden
  ("nixos: attic" = pull, "attic: ci token" = push, "attic: admin token");
  machines read the pull token from `/etc/nix/netrc`, never from this repo.
- Uploads to Attic go over Tailscale (`http://vps-main:8090`), not through
  Cloudflare, which rejects request bodies over 100 MB.
- **Don't run `nix flake update` locally.** CI updates `flake.lock` weekly
  and commits it only after every host built, so machines download instead
  of compiling. Change `flake.lock` only when adding or removing an input.
- **Every push to `main` deploys to all machines** once CI builds it
  (`built` branch, `modules/auto-upgrade.nix`). Treat `main` as production:
  evaluate every host before pushing. Never move `built` by hand.
- **Never change `system.stateVersion` or `home.stateVersion`.** They
  record each machine's first install.
- **Deck: never reset zoe's password as root** (`sudo passwd zoe`, or
  setting `hashedPassword`/`initialPassword` for zoe). Her home is fscrypt
  encrypted with only her login password as key and no recovery passphrase,
  so a root reset locks it permanently.
- **Deck: Jovian owns the display manager.** `jovian.steam.autoStart` turns
  on SDDM with auto-login itself. Don't enable another display manager or
  disable SDDM. Don't override `boot.kernelPackages` on the Deck: Jovian
  sets Valve's kernel.
- **Deck: the unlock path is fragile; run the `touch-unlock` VM test.**
  unl0kr (touch keyboard) only starts while Plymouth is *not* running, so
  `touch-unlock.nix` keeps Plymouth out of the initrd and starts it from the
  real root. Enabling Plymouth in the initrd there means no way to type the
  passphrase without a USB keyboard. The TPM enrolment is a manual step on
  the Deck (`sudo deck-tpm-enroll`); the passphrase must always keep working.
- **Desktop: sudo is passwordless for zoe** (`wheelNeedsPassword = false`),
  on purpose. Anything running as zoe is effectively root there, so run
  untrusted code and autonomous agents in Incus/Podman, not in her session.
- One look everywhere: colours and artwork come from `pkgs/artwork.nix`
  only. Don't hard-code the accent colour elsewhere.
- Keep 2 builds × 4 cores on the Deck (`nix.settings.max-jobs`/`cores`);
  more makes it swap.
- `hardware-configuration.nix` files come from `nixos-generate-config` on
  the real machine. Don't write or "fix" them by hand.

## Commits

- Message style: `scope: short summary` (e.g. `ci: ...`, `deck: ...`,
  `cache: ...`), body explaining what and why.
- Commits are SSH-signed; keep signing on.
- Every push to `main` starts a full CI run and **cancels the one in
  progress**. For changes that don't affect any build (docs like this
  file), put `[skip ci]` in the commit message.

## Installer ISO

- `installer/` builds a public download (https://nix.zoe.dev.br, uploaded by
  iso.yml over Tailscale to deploy@vps-main, which can only rsync into /srv/nix):
  keep it free software only (`nixpkgs.config.allowUnfree = false`).
- Hosts with `disko.nix` get their filesystems, LUKS and swap from disko.
  Their `hardware-configuration.nix` is generated with `--no-filesystems`;
  never add `fileSystems`/`swapDevices`/LUKS devices to it or to the host,
  or they'll clash with disko.
- Unfree software must never be *in* the image. Widevine and Claude Code
  are downloaded on the running installer by `installer-extras.service`
  (from Google/Anthropic, via nixpkgs); keep that pattern for anything unfree.
- The GUI (`gui.py`) never touches the machine itself: it runs
  `install-nixos` with `INSTALL_UI=1` and speaks its `@@STEP` / `@@ASK`
  protocol (documented at the top of the script). New questions go in the
  script through `ask_line` / `ask_hidden` / `ask_secret` so both the
  console and the GUI get them.
- `installer/troubleshooting.md` becomes Claude Code's CLAUDE.md on the live
  installer; keep its "never format" rules in sync with the resume logic.
- Test `install-nixos.sh` changes by building the ISO
  (`nix build .#installer-iso`; this also runs ShellCheck on the script) and
  GUI changes with the `installer-gui` VM test.
  Never run the script itself outside a VM: it erases a disk.
